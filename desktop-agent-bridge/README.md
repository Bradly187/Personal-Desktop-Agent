# Desktop Agent Bridge — VS Code Extension

Exposes a WebSocket server on `ws://127.0.0.1:8767` so the Personal Desktop Agent
Python backend can read IDE state and send edit commands without screen-scraping.

## What it provides

| Action | Description |
|--------|-------------|
| `get_editor_context` | Active file, language, cursor, selection, 50 lines context above/below, LSP diagnostics |
| `get_git_context` | Branch, ahead/behind, staged/unstaged files via VS Code git extension |
| `apply_edit` | Replace a range in any file — appears in undo history, triggers LSP re-validation. Backend gates the target path to the writable-root allowlist. |
| `run_terminal` | Run a command in the integrated terminal **and capture its output** (via VS Code shell integration, when available). Backend gates `cwd` to the writable-root allowlist. |
| `open_file` | Open file and jump to line |
| `get_diagnostics` | All workspace errors/warnings from language servers |
| `ping` | Health check |

## Security — authenticated WebSocket

The handshake requires a shared token (`?token=…`). The token is a 64-char hex
secret stored at `~/.claude/desktop_agent_bridge/token` (mode 0600), generated by
whichever side starts first — the extension on activation, or the Python backend
via `inference/bridge_protocol.py`. Connections without a matching token are
rejected (close code `4401`). This closes the previously-unauthenticated local
port: any process on the machine could otherwise drive `apply_edit` / `run_terminal`.

## Dev-agent model picker

Run **`Desktop Agent: Select Dev-Agent Model`** (or click the status-bar item) to
pin one model for *all* dev-agent queries (code / math / plan / general — and
vision when the model is image-capable), or choose **Auto** for the default
VRAM-aware domain routing.

- The backend publishes its model roster to `~/.claude/desktop_agent_bridge/roster.json`
  on startup; the picker reads it.
- Your choice is written to `override.json`; the backend's `ModelRouter` honors it
  on the next dev query. A pin that won't fit current VRAM silently falls back to
  Auto rather than failing. The accessibility command model is never overridden.
- The accessibility (voice/gesture) command path is unaffected.

## Installation

### Option A — Development install (recommended)

```bash
cd desktop-agent-bridge
npm install
npm run compile

# Install into VS Code
code --install-extension .
# or: copy desktop-agent-bridge/ to ~/.vscode/extensions/desktop-agent-bridge-0.2.0/
```

### Option B — VSIX package

```bash
cd desktop-agent-bridge
npm install -g @vscode/vsce
npm install
npm run compile
vsce package
# Installs: code --install-extension desktop-agent-bridge-0.2.0.vsix
```

## Usage

The extension activates automatically when VS Code starts. Look for the
status bar item in the bottom-right corner: `⊙ Agent: 0`.

Start the Python backend with `--vscode` to connect:

```bash
python main.py --vscode [other flags...]
```

The status bar updates to `🔌 Agent: 1` when the Python backend connects.

## Settings

| Setting | Default | Description |
|---------|---------|-------------|
| `desktopAgent.port` | `8767` | WebSocket port |
| `desktopAgent.contextLines` | `50` | Lines of surrounding context to send |

## Protocol

All messages are JSON. Request: `{ "id": "optional", "action": "...", ...params }`.
Response: `{ "id": "optional", "ok": true/false, "data": ..., "error": "..." }`.

## Commands

- `Desktop Agent: Restart Bridge Server` — restart the WebSocket server (e.g. after port conflict)
- `Desktop Agent: Show Bridge Status` — show connection count and the active dev model in a notification
- `Desktop Agent: Select Dev-Agent Model` — pin a model for dev-agent queries, or Auto

## Web access

The extension has **no outbound web access** — it is a localhost-only IDE bridge.
Web retrieval lives in the Python backend's `SEARCH_WEB` verb, where it is
content-filtered and logged.
